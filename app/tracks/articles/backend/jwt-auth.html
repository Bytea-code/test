JWT: سه اشتباه رایج که هنوز تکرار می‌شوند

ن نیما رستمی ۲۴ مهر ۱۴۰۵ ۸ دقیقه مطالعه

JWT ابزار خوبی است وقتی درست استفاده شود: یک توکن امضاشده که سرور بدون مراجعه به دیتابیس می‌تواند اعتبارش را بررسی کند. اما همین «بدون دیتابیس» بودن، مسئولیت‌هایی می‌آورد که اگر نادیده بگیری، امنیت را سوراخ می‌کند.

اشتباه اول: توکن در localStorage

هر اسکریپتی که روی صفحه اجرا شود (حتی یک کتابخانهٔ آلوده) می‌تواند localStorage را بخواند. برای اپ‌های مرورگری، کوکی HttpOnly و Secure انتخاب امن‌تری است چون جاوااسکریپت به آن دسترسی ندارد؛ در عوض باید مراقب CSRF باشی (SameSite=Strict یا Lax کمک می‌کند).

// سمت سرور: همیشه امضا و انقضا را بررسی کن
const payload = jwt.verify(token, SECRET, {
  algorithms: ["HS256"],   // اجازهٔ none نده
  maxAge: "15m",
});

اشتباه دوم و سوم

  • توکن بلندمدت بدون چرخش: access token کوتاه (۱۵ دقیقه) + refresh token چرخشی بساز.
  • اعتماد به payload بدون verify: اول امضا، بعد خواندن claims.
  • logout سمت کلاینت کافی نیست؛ refresh را سمت سرور باطل کن.
نکتهٔ منتور: الگوریتم را در verify صریح قفل کن؛ پذیرفتن هر الگوریتمی که توکن ادعا می‌کند، دروازهٔ حملهٔ «alg: none» است.
مقالهٔ قبلیAPI ای که شش ماه بعد هم خوانا بماند مقالهٔ بعدیایندکس پایگاه‌داده: کی و روی کدام ستون؟
