CI/CD با GitHub Actions: از پوش تا استقرار

آ آرش پناهی ۹ آبان ۱۴۰۵ ۸ دقیقه مطالعه

CI/CD یعنی هیچ تغییری بدون ماشینِ بررسی وارد نشود و هیچ انتشاری دستی و استرس‌زا نباشد. خوشبختانه یک فایل YAML کوچک، بیشترِ این وعده را محقق می‌کند.

خط لولهٔ حداقلی

name: ci
on: [push, pull_request]
jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run lint
      - run: npm test

شکست سریع، ارزان‌ترین شکست

ارزان‌ترین و سریع‌ترین بررسی را اول بگذار (لینت قبل از تست، تست واحد قبل از یکپارچه). هرچه زودتر قرمز شود، هزینهٔ اصلاح کمتر است. کش کردن npm هم زمان صف را نصف می‌کند.

نکتهٔ منتور: استقرار را به یک job جدا با environment محافظت‌شده ببر؛ این‌طور تأیید انسانی و rollback تمیز، بخشی از خط لوله می‌شود نه یک تصمیم لحظه‌ای.
مقالهٔ قبلیهرم تست و اولین تست شما ادامهٔ مسیرویدیوهای ابزار و دواپس
