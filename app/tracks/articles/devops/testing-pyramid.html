هرم تست و اولین تست شما

آ آرش پناهی ۲ آبان ۱۴۰۵ ۶ دقیقه مطالعه

هرم تست یک قانون بودجه است: تست‌های واحد ارزان و سریع‌اند، پس زیاد بنویس؛ تست‌های یکپارچه گران‌ترند، پس متوسط؛ تست‌های سرتاسر کند و شکننده‌اند، پس فقط برای جریان‌های حیاتی. وارونه کردن هرم یعنی CI کند و دیروقت‌فهمیدن باگ‌ها.

سه لایه

  • واحد: یک تابع یا ماژول، بدون شبکه و دیتابیس؛ میلی‌ثانیه‌ای.
  • یکپارچه: چند ماژول با هم، مثلاً router + دیتابیس آزمایشی.
  • سرتاسر: مرورگر واقعی و جریان کامل؛ فقط مسیرهای حیاتی.
test("validateTask عنوان خالی را رد می‌کند", () => {
  const fields = validateTask({ title: "  " });
  expect(fields).toEqual({ title: "عنوان الزامی است" });
});

چه چیزی را تست کنیم

تست خوب، رفتار را قفل می‌کند نه پیاده‌سازی را: ورودی/خروجی و حالت‌های مرزی (خالی، null، مرز عدد). اگر با هر ریفکتورِ بی‌تغییرِ رفتار، تست می‌شکند، تست به جزئیات چسبیده است.

نکتهٔ منتور: اولین تست را روی تابعی بنویس که دیروز باگ داشت؛ هم ارزش فوری دارد هم انگیزهٔ ادامه.
